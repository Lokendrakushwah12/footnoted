Question answering over documentation

Answers that quote their source, or say they don’t know.

footnoted answers questions over 1,040 pages of Python, MCP and Claude documentation. Every claim must carry a quote that is checked against the page, and a question the docs cannot answer is declined. Every figure on this page has a footnote to the file and command that produced it.

Architecture

One question, eight steps

There is no framework underneath. The index is one SQLite file and a numpy matrix, the model is Qwen 2.5 3B served by Ollama, and the whole project is 1,438 lines of Python.

  1. ChunkPages are split on headings into pieces of at most 1,200 characters, each prefixed with its page title and section.
  2. Index31,777 chunks go into SQLite FTS5 for BM25 and into a matrix of bge-small vectors.
  3. RetrieveKeyword and vector rankings are fused, with vectors weighted double and at most two chunks per page.
  4. BudgetThe context assembler fits instructions, question and passages into the model’s 4,096-token window. It cannot overflow.
  5. DraftThe model answers as a list of claims. Each claim names a passage and quotes it.
  6. GroundA claim is kept only if its quote’s words appear, in order, in a retrieved passage.
  7. VerifyA second call checks that the claims answer the question and that each one is backed by its quote.
  8. Answer, or declineIf nothing survives, the query is rewritten and retried twice. After that the system says it cannot answer.

Memory

The last four turns are kept verbatim. Older ones are compressed into summaries and durable facts with an expiry date, and used to rewrite a follow-up such as “how do I make it ignore case?” into a full question.

Knowledge graph

394 entities and 496 relations extracted from the MCP specification, walked two hops from the entities a question names. Built and measured, and not wired into answering, for the reason given below.

Eval gate

Every run records its path through the steps above. CI fails a change whose scores fall below the accepted run, whose path is illegal, or whose scorecard is older than the code.

Money and time

What it costs to run

Money

Nothing was spent. The model is free and runs on the laptop, the index is two 47 MB files, and there is no hosted service, vector database or API key anywhere in the stack.

Token totals per question were not recorded, so there is no per-question price to quote. What is known: the largest prompt sent was 1,886 tokens and every reply is capped at 600.3 A hosted model is a change of three environment variables.

Impact

What this is evidence of, and what it is not

footnoted has no users. Its impact is what the measurements show and the decisions they changed.

What held up

  • Declining works. 11 of 12 questions the docs cannot answer were declined, including five about third-party Python libraries the model knows well.
  • The gate catches regressions. Re-recording unchanged code moved the score by one question and passed. Cutting retrieval to one passage moved it from 31 to 19 and failed, listing each question that got worse.7
  • Memory resolves follow-ups without harming complete questions.

What did not, and the limits

  • The 3B model is the ceiling. It converts 60 good retrievals into 31 grounded answers. A larger model is untested.
  • Reranking and the knowledge graph did not earn their place.
  • The evals are small and were written by the builder: 84 questions, 30 memory cases and 26 graph cases. Retrieval settings were tuned on the questions they are reported on.
  • The gate’s model judge failed calibration, agreeing with a key-term check on 26 of 34 answers, so it is reported and never gated on.2
Footnotes

Where each number comes from

  1. Retrieval evals: evals/python.jsonl (46 questions) and evals/docs.jsonl (26). Run uv run footnoted eval evals/python.jsonl evals/docs.jsonl. Median times are for the Python set. The 0.61 figure is the same eval before question words were dropped.
  2. The accepted answer-loop run: evals/golden.json, 72 answerable and 12 unanswerable questions. Run uv run footnoted gate record, which takes about nine minutes and needs the local model.
  3. Two full runs of the same 84 questions, one capped at five passages and one offered twelve. The eval prints the largest real prompt. Described in the README, “Context budget”.
  4. evals/memory.jsonl, 30 cases. Run uv run footnoted eval-memory evals/memory.jsonl -v.
  5. evals/graph.jsonl, 12 two-page questions and 14 controls. Run uv run footnoted graph build, then uv run footnoted eval-graph evals/graph.jsonl.
  6. Timed once with time uv run footnoted ingest. This is slower than the embedding model should be and has not been investigated.
  7. uv run footnoted gate check compares evals/scorecard.json with evals/golden.json and runs on every push in GitHub Actions. Both directions of the test are in the README, “Eval gate”.
